- Several frameworks offer handy mass-assignment features to lessen the workload for developers. Because of this, programmers can directly insert a whole set of user-entered data from a form into an object or database. This feature is often used without a whitelist for protecting the fields from the user's input. This vulnerability could be used by an attacker to steal sensitive information or destroy data

- ## Exploiting Mass Assignment Vulnerability
# Mass Assignment - Registration Approval Bypass

## Scenario
- A user registers on the application but receives **"Account is pending approval"** when trying to log in.
- The source code reveals that login is only allowed if the `confirmed` field is `True`.

## Vulnerable Code
```python
if request.form['confirmed']:
    cond = True
```

- During registration, the application directly trusts the `confirmed` parameter from the HTTP request.
- If `confirmed` is present, the account is stored with `confirmed=True`.

## Exploitation
1. Register a new user.
2. Intercept the POST request to `/register` using Burp Suite.
3. Add the parameter:
   ```
   confirmed=test
   ```
4. Forward the request.
5. Log in with the new credentials.

## Result
- The account is created as **approved**.
- Administrator approval is bypassed.
- The user can log in immediately.

> **Key Takeaway:**  
> A **Mass Assignment** vulnerability occurs when an application blindly binds user-supplied parameters to internal model fields, allowing attackers to modify sensitive attributes (e.g., `confirmed`, `isAdmin`, `role`) that should only be controlled by the server.
