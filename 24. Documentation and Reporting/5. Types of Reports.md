# Assesment types
1. `Vulnerability Assessment` : automated scan (authenticated/unauthenticated) to enumerate vulns; no exploitation, only validation to filter false positives.
2. `Internal vs External (scan)` : external = anonymous internet user vs public systems; internal = scanner behind the firewall (can be anonymous or credentialed).
3. `Penetration Testing` : goes beyond scans, uses scan data to guide exploitation; perspectives — `blackbox` (company name/network conn only), `greybox` (in-scope IPs/CIDRs), `whitebox` (credentials, source code, configs).
4. Evasion levels : `zero evasion` (uncover max vulns), `hybrid evasive` (start evasive, get noisier until detected, then go non-evasive), `evasive` (stay undetected like an advanced attacker; adversary sim can span months).
5. `Internal vs External (pentest)` : external = anonymous internet attacker using OSINT against internet-facing hosts; internal = anonymous or authenticated user aiming for foothold, privesc, lateral movement, AD compromise.

# Inter-disciplinary assessments
6. `Purple Team` : red+blue — pentester simulates a threat while incident responder reviews tooling/alerting.
7. `Cloud Focused Pentesting` : conventional pentest + cloud architecture knowledge to abuse things like secrets/keys, containers, serverless.
8. `Comprehensive IoT Testing` : specialists cover network, cloud, application (and hardware) components of IoT platforms.
9. `Web App Pentesting` : app-only role-based vuln testing, or app + infrastructure where initial compromise comes through the app.
10. `Hardware Pentesting` : physical testing of IoT devices, laptops, kiosks/ATMs; set RoE first, especially for destructive testing.

# Report types
11. `Draft Report` : submitted first for client feedback (management response, wording, layout) before finalizing.
12. `Final Report` : issued after client review/sign-off; auditors won't accept a draft for compliance.
13. `Post-Remediation Report` : retest only original findings/hosts after fixes; time-box it to keep an apples-to-apples comparison.
14. `Attestation Report` : 1-2 page letter for third parties — no technical details, just finding counts, approach, general comments.

# Other deliverables
15. `Slide Deck` : presentation for technical or executive audiences; use anecdotes/current events, not just graphs and numbers.
16. `Spreadsheet of Findings` : tabular findings for sorting/import into ticketing; use pivot tables by severity/category; no narrative.
17. `Vulnerability Notification` : out-of-band alert for critical findings (e.g., internet-exposed unauth RCE, sensitive data exposure); keep to technical details + tool evidence.
