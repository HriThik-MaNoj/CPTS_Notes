# PATH Abuse

## What is PATH?
- `PATH` is an environment variable that contains directories where the shell looks for executables.
- This lets you run commands without specifying their full path (e.g., `cat` instead of `/bin/cat`).

## Check PATH
```bash
echo $PATH
env | grep PATH
```

## Find Current Directory
```bash
pwd
```

## Key Concept
- Any executable placed in a directory listed in `$PATH` can be run from anywhere.
- Example: A script in `/usr/local/sbin` can be executed from `/tmp` without specifying its full path.

## Add Current Directory to PATH (Dangerous)
```bash
PATH=.:$PATH
export PATH
echo $PATH
```

- `.` represents the current working directory.
- If `.` is first in `PATH`, the shell searches the current directory before system directories.

## PATH Abuse Example
Create a fake `ls` command:

```bash
touch ls
echo 'echo "PATH ABUSE!!"' > ls
chmod +x ls
```

Run it:

```bash
ls
```

Output:
```text
PATH ABUSE!!
```

## CPTS Exam Notes
- Enumerate PATH:
  ```bash
  echo $PATH
  env | grep PATH
  ```
- Look for writable directories inside `$PATH`.
- Check if `.` is present in `$PATH` (especially at the beginning).
- If a privileged process executes commands without absolute paths, it may be vulnerable to PATH hijacking.
- Always use absolute paths (e.g., `/bin/ls`) in privileged scripts to prevent PATH abuse.
